# Планировщик съёмки

Программа распределяет конкретные борта со своих ВПП по районам съёмки и строит маршруты, которые не заходят в запретные зоны. Есть консольный расчёт и карта в браузере.

Подробный ход алгоритма — в [АЛГОРИТМ.md](АЛГОРИТМ.md).

## Что нужно

- Windows, Python 3.14
- пакеты: `shapely`, `pyproj`, `matplotlib`, `numpy`
- браузер для карты (OpenLayers подгружается с CDN)

Код рассчитан на интерпретатор `C:\Python314\python.exe`. Системный Python без `shapely` и `pyproj` не подойдёт.

## Развёртывание

Папка проекта внутри репозитория называется `drone_planner`. Из корня `flight-planning`:

```powershell
cd drone_planner
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Карту можно поднять одной командой. Скрипт сам создаст `.venv`, поставит пакеты и откроет сервер на порту 8765:

```powershell
cd drone_planner
.\start.bat
```

Если виртуальное окружение создавалось на другой машине, в `.venv\pyvenv.cfg` путь `home` должен указывать на установленный Python, например `C:\Python314`.

На Windows консоль лучше запускать в UTF-8, иначе символ `км²` в выводе ломается:

```powershell
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"
```

Рабочая директория — корень проекта. Оттуда консоль читает `zones.geojson` и `bases.geojson`, карта загружает `vpp.geojson` и `polygons.geojson`, результаты пишутся в `assignment.json` и `paths.png`.

## Два способа работы

| Способ | Что делает | Данные |
|---|---|---|
| Консоль | назначение бортов, затем галсы в PNG | `zones.geojson`, `bases.geojson` |
| Карта | то же назначение плюс маршруты на карте | `vpp.geojson`, `polygons.geojson` |

Перекрытие всегда 50%. Разрешение пользователь задаёт в **метрах на пиксель**. Внутри оно переводится в сантиметры на пиксель: ввод `0.05` это 5 см/пиксель. Число `5` без нуля это 5 м/пиксель — слишком грубо, галсы могут не поместиться в район.

На каждой ВПП стоит свой парк: 4 Геоскан 201, 2 Геоскан 801, 2 Genimi. Борт взлетает и садится только на свою площадку. Камера подбирается под тип района.

## Карта

Сервер раздаёт страницу и считает задачу:

```powershell
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe web_server.py
```

Откройте [http://127.0.0.1:8765](http://127.0.0.1:8765). Щелчок по карте ничего не ставит. В корне проекта уже лежат файлы для карты:

- `vpp.geojson` — точки ВПП;
- `polygons.geojson` — районы съёмки и запретные зоны.

Их нужно загрузить кнопками:

1. **Загрузить ВПП** — `vpp.geojson`. У точки свойство `vpp` от 1 до 6 или имя вида `ВПП-1`.
2. **Загрузить районы** — `polygons.geojson`. В файле полигоны съёмки и запретные зоны.

Кнопка **Рассчитать** доступна, когда есть хотя бы одна ВПП и один район. После расчёта под картой три критерия: минимальное время, минимальный ресурс, время и ресурс. Выбранный критерий рисует свои галсы, перелёты с ВПП и перегоны между галсами. Цвет борта в легенде совпадает с квадратом в списке назначений.

Сплошная линия — галс, пунктир — перелёт с ВПП и обратно, точки — перегон между галсами. Запретные зоны штрихуются и в площадь съёмки не входят. Маршруты их не пересекают.

План режима «минимальное время» дополнительно пишется в `assignment.json`.

Если после правки кода страница ведёт себя по-старому, остановите процесс на порту 8765 и запустите `web_server.py` снова, затем обновите вкладку.

## Консоль

Сначала назначение:

```powershell
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe main.py
```

Программа читает `zones.geojson` и `bases.geojson`, спрашивает разрешение в м/пиксель, печатает три режима и сохраняет режим времени в `assignment.json`.

Затем маршруты:

```powershell
$env:PYTHONUTF8 = "1"
.\.venv\Scripts\python.exe main_paths.py
```

Снова спрашивается разрешение. Назначение берётся из `assignment.json`, галсы рисуются в `paths.png`. Если PNG открыт в просмотре, запись может завершиться ошибкой «Invalid argument»: закройте файл и запустите снова.

Консольный `main.py` камеры по типам районов не делит: все борта создаются как видимые. Разные типы съёмки и запретные зоны учитываются на карте.

## Формат файлов

Координаты — WGS84, долгота и широта.

**ВПП**, точка:

```json
{
  "type": "Feature",
  "properties": { "name": "ВПП-1", "vpp": 1 },
  "geometry": { "type": "Point", "coordinates": [38.855586, 56.511863] }
}
```

**Район съёмки**, полигон. `survey_type`: `visible`, `multispectral` или `thermal`. Если поля нет, район считается видимым.

```json
{
  "type": "Feature",
  "properties": {
    "name": "Район 4",
    "kind": "survey",
    "survey_type": "visible"
  },
  "geometry": { "type": "Polygon", "coordinates": [[[lon, lat], ...]] }
}
```

**Запретная зона.** `kind` должен быть `forbidden`. Можно `Polygon` или `MultiPolygon`: каждая часть рисуется отдельно, для расчёта это всё равно запрет, а не район.

Готовые GeoJSON лежат в корне проекта:

| Файл | Что внутри |
|---|---|
| `vpp.geojson` | точки ВПП для карты |
| `polygons.geojson` | районы съёмки и запретные зоны для карты |
| `bases.geojson` | базы для консоли |
| `zones.geojson` | зоны для консоли |

## Что смотреть в результате

В списке назначений у каждого борта район, имя, площадь в км² и цветной квадрат того же цвета, что галсы на карте.

`T` — время самого долгого района в часах, районы снимаются параллельно. `R` — суммарный расход ресурса в процентах.

Типичные сообщения:

- нет камеры нужного типа или не хватает запаса хода — борт до района не долетает или камера не подходит;
- район закрыт запретными зонами — после вычитания запретов снимать нечего;
- ВПП внутри запретной зоны — перелёт построить нельзя;
- `paths.png` не записался, маршруты в терминале уже есть — файл был открыт.
